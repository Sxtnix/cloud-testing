4. AWS  (EC2 + API Gateway)
===============================================================================

4.1  SECURITY GROUP DE EC2 - abrir:
       22      SSH
       80      frontend
       443     frontend HTTPS (si aplica)
       8081-8083  integraciones del API Gateway
     NO abrir:
       5672 / 15672  (RabbitMQ - interno)
       9092 / 9093 / 9094  (Kafka - interno; 9094 además ya está en 127.0.0.1)
       8084          (ms-email: no recibe tráfico público)
       8085          (ms-pagos: solo lo llama ms-carrito por la red de Docker)
       8086          (ms-monitoreo: consulta el broker por la red de Docker)
       4200          (eso es el ng serve local, aquí no existe)
     Nota: el puerto 18081 es un mapeo SOLO local del compañero; en EC2 es
     el 8081 normal.

4.2  API GATEWAY (AWS Console -> API Gateway -> tipo HTTP API)
     Si reutilizan el existente (st3wqbtin7...): NO cambiar nada.
     Si crean uno nuevo -> apuntar rutas a la IP pública de EC2:
         /productos/...  ->  http://<EC2>:8081/...
         /usuarios/...   ->  http://<EC2>:8082/...
          /carrito/...    ->  http://<EC2>:8083/...
          /pedidos/...    ->  http://<EC2>:8083/...
          (ms-email NO necesita ruta pública; ms-pagos TAMPOCO: es interno.
           ms-monitoreo TAMPOCO: se consulta en la propia EC2)
     Crear el stage (el actual se llama "desarrollo") -> copiar la URL base ->
     pegarla en environment.prod.ts (paso 2.1) y listo.

4.3  EN EL SERVIDOR EC2:
         git clone <URL del repositorio>
         cd desarrolloCloudNative-main-merged
         nano .env                      # pegar contenido del paso 3.3
         docker compose up -d --build
     El frontend se compila DENTRO de Docker con "npm run build" = build de
     PRODUCCIÓN -> usa environment.prod.ts automáticamente. Si después cambian
     environment.prod.ts o un SecurityConfig, recuerden reconstruir:
         docker compose up -d --build <servicio>

4.4  CHECKPOINT HTTPS (revisar ANTES de prometer el login)
     - El redirectUri de producción es https://... y Azure NO acepta http
       salvo en localhost.
     - El nginx del contenedor frontend solo escucha en el puerto 80 -> hace
       falta algo delante que termine el TLS. Opciones:
         a) Dominio + certificado (Let's Encrypt / nginx en el host / ALB)
         b) Cloudflare Tunnel (gratuito, no abre puertos)
         c) ALB de AWS con certificado ACM
     - OJO: con IP pura (44.200.146.153) Let's Encrypt NO emite certificados.
       Si no hay solución HTTPS todavía, el login de Azure va a fallar con
       AADSTS50011 / error de conexión.

6. ERRORES COMUNES Y SU CAUSA
===============================================================================
  AADSTS50011 (error de redirección)
      -> La URI pública no está registrada en Azure. Ver paso 1.1.

  401 con WWW-Authenticate: Bearer error="invalid_token"
      -> El token es de otro tenant: revisar AZURE_ISSUER_URI (3.2) y
         azureTenantId (2.1) que coincidan con el tenant de Azure.

  "Blocked by CORS policy" / falla solo en OPTIONS
      -> Falta el origen del frontend en los 6 SecurityConfig.java (3.1).
         Ojo: el origen es EXACTO (protocolo + host + puerto), sin barra final.

  Funciona en local pero en AWS "no inicia sesión" / error de conexión
      -> Falta HTTPS. Ver CHECKPOINT 4.4.

  403/550 en los correos (Authentication failed / Bad credentials)
      -> MAIL_PASSWORD malo o revocado. Generar otra "app password" de Gmail
         y actualizar el .env:  docker compose up -d ms-email

  El usuario entra pero no ve productos / no puede comprar
      -> Revisar URL de API Gateway en environment.prod.ts (2.1) y volver a
         construir el frontend.

  "No cargan los productos" en LOCAL con authBypass: false
      -> Todavía no se inició sesión con Microsoft: el interceptor de MSAL
         retiene las llamadas. Iniciar sesión (o authBypass: true solo para
         pruebas locales sin Azure). Ver sección 2.2.

  Catálogo vacío en el primer despliegue
      -> La siembra solo se hace con la base VACIA. Si se apunta a una BD
         con datos no se toca; si se quiere cargar a mano: CATALOGO_SEED=false
         y cargar por API/SQL.
